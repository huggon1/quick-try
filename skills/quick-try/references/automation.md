# Bounded automation (conditional support)

Support only a real one-shot or replay route that completes a meaningful loop in the approved time. A small collector run, transformation pipeline, or local notification preview may qualify. Benefits requiring weeks of scheduling, production operation, or team adoption remain outside the trial's conclusions.

Use a familiar input slice and disposable state. Inspect effect destinations: sending messages, publishing, writing external records, or scheduling future runs requires the appropriate explicit scope. Prefer target-supported local sinks and test resources. A dry-run that only prints a plan cannot show the delivery behavior; explain exactly what it can demonstrate.

Let the user change an input, filter, or rule and rerun from a preserved baseline. Show the actual output and which steps ran. Keep live-source execution distinct from historical replay and synthetic fixtures. Real credentials and live data are not implied by a request to try the project.

Provide stop and fresh-run controls; do not leave a recurring job active after a short trial. If there is no safe bounded execution path, say this project needs a different setup and offer an authentic accessible demo if one exists.
