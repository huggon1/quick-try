# Multi-turn collaboration

Use for agents, behavior-changing skills, or prompts whose benefit appears through conversation. Extract a collaboration promise such as easier starts, clearer decisions, or better handling of changing requirements.

Choose a familiar, unfinished but bounded task: a small design choice, a draft needing revision, or a reproducible issue in a copied project. Keep enough ambiguity for the user to make choices. Avoid a trivial puzzle with one predetermined answer and avoid completing the task during preparation.

Prepare a fresh session with the real target loaded through its supported mechanism, the relevant material, and a brief initial request. Confirm activation from available runtime evidence; if native loading cannot be checked, label it unverified. A text injection, different model, or inherited coordinator session changes the conditions and must be disclosed.

Use the host adapter from preparation.md. A transcript or noninteractive CLI result can be a demonstration but cannot replace a promised session the user can continue.

Let the user pursue the task however they like. Changing direction or asking for explanation are possibilities, not prescribed second and third turns. Do not preload instructions that coach the target toward the desired outcome. The user's natural reactions determine whether the collaboration is easier or irritating. Formal A/B is optional only when requested and budgeted; the user's familiarity with their normal workflow is often sufficient context for an impression.

A skill such as i-have-adhd might use one current planning problem copied into a clean session. The entry can simply say: “材料已经放好了，继续推进这件事就行，随时可以改主意。” Record any repetition, useful next step, or omission only if actually observed.
