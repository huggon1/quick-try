# Generate and revise

Use for models and tools whose core loop is input, generation, inspection, and revision. Identify the promised change in a concrete artifact: a draft for a known audience, a picture for an actual concept, or a short audio sample with a clear use.

Prepare one relevant seed and a few editable controls supported by the original product. Use the actual model/tool, identify the version when available, and confirm access, input support, output location, and budget before calling it. Local access to a source image or document does not authorize external processing.

Preserve seeds and outputs separately. A representative smoke generation can be useful, but leave an editable fresh starting point. Keep the interface native when its editing controls or iteration experience are part of the promise; an API response cannot establish that UI experience.

Let the user revise content, intent, style, or constraints freely. Avoid a fixed prompt ladder. Retain attempts the user wants to discuss, including disappointing outputs. Never relabel agent-generated output as a user's chosen result.

If required quota or provider access is unavailable, offer a smaller real trial or report the blocker. A simulated image, substituted model, or screenshot of an author's example is not a completed target trial.
